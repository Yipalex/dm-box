# 私信匣 · DMBox ![logo](extension\icons\icon32.png "logo")

> *A Leo's box for an Aries' whispers.* — 狮子座为白羊座私语准备的匣子。

把你和某个联系人（或全部联系人）的微博私信聊天记录**备份到自己的电脑或 NAS 上**，支持**增量备份**、媒体文件下载、全文搜索、日历跳转和漂亮的 HTML 导出。

- **只读**：不调用任何写接口（不发私信、不标已读），账号行为严格限制在"浏览历史"语义内
- **保守限速**：每页请求间隔 5–10 秒随机抖动、每 10 页长休 45–90 秒、遇限流指数退避、每日请求上限 400 次——宁慢勿快，把封号风险降到最低
- **自有存储**：默认连接本机 `127.0.0.1:8765`，也可连接自有 NAS / VPS；数据保存在服务端指定目录，不上传到项目方。远程模式会将消息和下载附件所需的微博登录 Cookie 发送到你配置的服务。

## 部署方式

- **本机使用**：按下方「快速开始」运行，默认仍使用项目里的 `data/`。
- **NAS Docker（推荐用于大容量存储）**：服务与数据都放 NAS，电脑仅运行 Chrome 扩展。参见 [NAS Docker 部署、迁移与远程访问](docs/nas-deployment.md)。
- **外接硬盘**：可通过 `DMBOX_DATA_DIR` 指定已存在的绝对路径；详情见部署文档。

## 系统组成（默认本机模式）

```
┌─────────────────────────┐      POST JSON       ┌──────────────────────────┐
│ Chrome 插件              │  ──────────────────▶ │ 备份服务 (FastAPI)        │
│ 在微博私信页注入备份面板    │   127.0.0.1:8765    │ SQLite + 媒体下载 + 导出   │
│ · 主动翻页拉取(保守限速)   │                      │ · 管理界面(联系人/搜索)    │
│ · 被动捕获(你翻看时顺路存) │                      │ · HTML 导出               │
└─────────────────────────┘                      └──────────────────────────┘
```

- **全量备份**：从最新消息向更早翻页（`mid` 游标），直到拉完
- **增量备份**：从最新往回拉，碰到数据库里已有的 `mid` 就停——通常一两页就完成
- **被动捕获**：你自己正常翻看聊天时，插件把微博页面"顺路"返回的数据存下来，零额外请求

## 快速开始

### 第 1 步：启动本地服务

需要 Python 3.10+（部分 macOS 自带版本较旧，需要另行安装）。**双击项目里的 `start.command`**（Windows 用 `start.bat`）。
首次运行会自动安装依赖，然后浏览器会打开管理界面 <http://127.0.0.1:8765>。

> 命令行方式：`./.venv/bin/python -m uvicorn server.app:app --host 127.0.0.1 --port 8765`

### 第 2 步：安装 Chrome 插件（开发者模式，2 分钟）

1. 打开 Chrome，地址栏输入 `chrome://extensions` 回车
2. 打开右上角的 **「开发者模式」** 开关
3. 点击左上角 **「加载已解压的扩展程序」**
4. 选择本项目里的 **`extension` 文件夹**
5. 完成！工具栏会出现橙色聊天气泡图标
6. NAS 用户：点击扩展图标，填写服务地址和访问密钥，点「保存并测试连接」，允许访问该地址后刷新微博私信页。本机默认配置无需更改。

### 第 3 步：开始备份

1. 登录微博后打开私信页：<https://api.weibo.com/chat>（点插件图标里的按钮也行）
2. 页面右下角会出现 **「私信备份助手」面板**，绿点表示已连上备份服务
3. 点 **「加载联系人」** → 在下拉框选择要备份的人
4. 第一次点 **「全量备份」**，之后日常点 **「增量备份」**（或选「全部联系人(增量)」）
5. 备份过程中**保持该标签页开着**；进度和日志都在面板里
6. 通过扩展弹窗打开管理界面，查看、搜索、导出 HTML（本机默认为 <http://127.0.0.1:8765>）

### 增量备份的日常用法

- 手动：隔几天打开私信页点一次「增量备份」，几秒到几十秒完成
- 自动：勾选面板里的「打开本页超过 24h 未备份时自动增量」，以后只要打开私信页就会自动补齐
- 顺路：平时正常翻看聊天记录，看到的内容会被被动捕获自动入库（零额外请求）

## 速率与风控策略（为什么慢）

| 策略 | 默认值 |
|---|---|
| 每页（200 条）请求间隔 | 5–10 秒随机 |
| 每 10 页（约 2000 条）长休 | 45–90 秒 |
| 多联系人之间休息 | 30–60 秒 |
| 每日主动请求上限 | 400 次（约 8 万条消息） |
| 遇 HTTP 414/418/432 或"访问频次过高" | 退避 2→4→8…分钟，连续 3 次即停止当天 |

一万条历史记录大约需要 8–15 分钟拉完；几十万条建议分几天跑（每天会自动在上限处停下，进度已保存，第二天接着增量即可）。**不要修改参数求快**——微博风控对高频规律请求敏感，慢就是稳。

> ⚠️ **风险告知**：本工具只读、限速保守，封号风险低但非零（更可能出现的是临时验证码/限流）。如果备份中出现验证码或面板提示连续限流，请停止当天操作。请仅用于备份你自己账号的私信。

## 跨平台支持（macOS / Windows）

核心代码（Python + FastAPI + SQLite）完全跨平台，Chrome 插件两边一样。差异只在启动脚本和两个可选的系统能力：

| 能力 | macOS | Windows |
|---|---|---|
| 启动本地服务 | 双击 `start.command` | 双击 `start.bat` |
| 防止运行时休眠 | 已内置 `caffeinate`（自动） | 控制面板→电源选项设为「从不睡眠」，或运行时用 `powercfg` |
| 语音 AMR→M4A 转码 | 自带 `afconvert`，开箱即用 | 需自行安装 [ffmpeg](https://www.gyan.dev/ffmpeg/builds/) 并加入 PATH；不装则语音存为 `.amr`（仍可下载，只是浏览器里点不开） |
| 开机自启后台常驻 | `./scripts/install_autostart.sh`（launchd） | 把 `start.bat` 的快捷方式放进「启动」文件夹（Win+R 输入 `shell:startup`） |

> Windows 用户：先装 [Python 3.10+](https://www.python.org/downloads/)（安装时勾选 "Add Python to PATH"），然后双击 `start.bat` 即可，其余步骤与 macOS 完全一致。

### 常驻运行（macOS）

- `start.command` 已内置 `caffeinate`：服务运行期间系统不会自动休眠（屏幕可以关，合盖仍会睡）
- 想让服务**开机自启、后台常驻**：终端运行一次 `./scripts/install_autostart.sh`，以后不用再双击启动；卸载用 `uninstall_autostart.sh`

> 注意（两个平台都适用）：**主动备份时浏览器标签页要保持在前台**。Chrome 会对后台标签限流定时器，备份会变得很慢；媒体下载由本地服务负责，不受此影响。

## 数据存放与格式

本机默认位于项目的 `data/`；Docker 模式位于映射到容器 `/data` 的 NAS 文件夹。设置 `DMBOX_DATA_DIR` 后，数据库、媒体和导出会一起使用该目录。服务与 SQLite 数据库必须位于同一台设备，避免把数据库放到另一台机器的 SMB/NFS 共享目录。

```
data/
├── weibo_dm.db        # SQLite 主存储（消息 + 原始 JSON + 联系人 + 同步日志）
├── media/             # 图片/视频/语音，按 SHA256 去重落盘
└── exports/           # 导出的 HTML 阅读视图
```

- 每条消息以 `mid` 为主键去重，**原始 JSON 整条入库**，未来可重建任意导出格式
- 媒体文件下载自带 `Referer: https://weibo.com`（绕过 sinaimg 防盗链），按内容哈希去重
- 想看原始数据：任何 SQLite 工具（如 [DB Browser for SQLite](https://sqlitebrowser.org)）打开 `weibo_dm.db` 即可

> 注意：本插件依赖微博**未公开接口**，且需要配合本地服务才能用。公开上架前建议在商店描述里写清楚使用前提，否则容易收到差评或被举报误判。**个人/小范围使用推荐"加载已解压"或直接分发 zip。**

## 常见问题与故障排查

### 运行了脚本，但管理页面打不开

Chrome 扩展和本地服务是两个独立部分：**安装扩展不代表本地服务已经启动**。脚本显示「启动中」或自动打开浏览器，也不代表启动成功。

1. 双击 `start.command`（Windows 用 `start.bat`），查看终端最后几行。正常启动应出现 `Application startup complete` 和 `Uvicorn running on http://127.0.0.1:8765`；如果出现报错，按下表处理。
2. 打开 <http://127.0.0.1:8765/api/health>。能看到包含 `"ok":true` 的 JSON，说明服务已连通；然后打开 <http://127.0.0.1:8765/>。
3. 手动启动时保持终端运行；按 Ctrl+C、退出终端或重启电脑后，需要重新启动。安装了开机自启的 macOS 用户可查看 `data/server.log`。

| 现象或报错 | 原因与处理 |
|---|---|
| `Connection refused` / `ERR_CONNECTION_REFUSED` | 通常是服务没有启动或已退出。先检查终端错误，确认端口是否监听。 |
| `No such file or directory` / `bad interpreter`，路径指向旧目录 | 项目搬过位置，虚拟环境里的启动程序仍引用旧路径。优先运行最新版 `start.command`；手动启动使用 `./.venv/bin/python -m uvicorn server.app:app --host 127.0.0.1 --port 8765`，避免直接执行旧的 `uvicorn` 文件。 |
| `.venv/bin/python` 不存在或无法执行 | 旧环境依赖的 Python 可能已被卸载或升级替换。最新版 macOS 启动脚本会保留旧环境为 `.venv.backup.时间戳`，重新创建环境并安装依赖。 |
| 提示需要 Python 3.10 或更新版本 | 安装 Python 3.10+ 后重试。macOS 自带的 Python 可能只有 3.9；脚本也会查找 Homebrew 常见位置的较新版本。 |
| `No module named ...` / `ModuleNotFoundError` | 依赖未装齐。在项目目录运行 `./.venv/bin/python -m pip install -r server/requirements.txt`；Windows 使用 `.venv\Scripts\python -m pip install -r server\requirements.txt`。安装时需要网络。 |
| `Address already in use` / 端口被占用 | 8765 已被其他进程占用。先访问健康检查地址；如果是本服务且正常，无需重复启动。否则确认占用程序后再关闭它。扩展固定连接 8765，单独修改服务端口会导致扩展断开。 |
| 依赖安装长时间无输出或提示连接超时 | 首次安装或修复需要下载依赖，脚本默认减少安装输出。检查网络、代理及终端错误；可用上面的安装命令查看详细进度。 |
| 浏览器刚打开就报错，但终端随后显示启动成功 | 浏览器可能比服务更早打开，等待几秒后刷新。 |

macOS 可在**项目目录**运行以下命令辅助判断：

```bash
# 查看 8765 是否有程序监听；无输出通常说明服务没有运行
lsof -nP -iTCP:8765 -sTCP:LISTEN

# 绕过命令行代理，直接检查本机服务
curl --noproxy '*' --max-time 5 http://127.0.0.1:8765/api/health
```

如果直接检查成功，而浏览器失败，检查代理软件是否绕过 `127.0.0.1`、`localhost`，并确认地址是 **http** 而非 https。命令行中存在 `ALL_PROXY` 等设置时，普通 `curl` 也可能错误地通过代理访问本机，因此排查时使用上面的 `--noproxy '*'`。

### 项目迁移、Python 升级后无法启动

`data/` 是聊天记录和附件所在位置；`.venv/` 是可重建的 Python 运行环境。**不要通过删除 `data/` 来修复启动问题。**

- **macOS**：保留整个项目和 `data/`，迁移后运行最新版 `start.command`。它会检查解释器是否能运行、补装缺失依赖；解释器失效时会备份并重建环境。能运行但版本低于 3.10 的旧环境需要手动移走 `.venv/` 后重试。
- **Windows / 跨系统迁移**：不要复用另一台电脑或另一系统的 `.venv/`。关闭服务后，将旧 `.venv/` 改名保留，再运行 `start.bat` 重新安装；确保本机已安装 Python 3.10+。
- **已安装 macOS 开机自启**：迁移后先确认手动启动正常，按 Ctrl+C 停止手动服务，再运行 `./scripts/install_autostart.sh`，更新自启配置里的项目路径。修复运行环境不会自动更新以前安装的自启路径。

### 管理页面能打开，但扩展仍显示红点

NAS 用户先在扩展弹窗确认服务地址和访问密钥，点击「保存并测试连接」并授予地址权限。401 表示密钥缺失或错误；网络错误应检查地址、HTTPS 证书、NAS 防火墙与端口映射。浏览器管理页面的登录状态不会代替扩展密钥。

先确认健康检查地址能正常返回，然后到 `chrome://extensions` 确认扩展已启用。更新扩展或搬动扩展文件夹后，必要时重新选择当前项目的 `extension` 文件夹加载，并**刷新微博私信页**，让页面载入新的内容脚本。管理服务重启后也可刷新私信页重新连接。

### 加载联系人失败、备份变慢或中断

- **加载联系人失败**：确认已登录微博，且当前页是 <https://api.weibo.com/chat>。本地健康检查正常只说明备份服务可用，不代表微博登录或接口正常。
- **备份变慢**：请求间隔、长休和每日上限属于内置限速；主动备份时保持微博标签页在前台。电脑休眠或合盖也会暂停工作。
- **遇验证码、访问频次过高或连续限流**：停止当天主动备份，按页面提示处理，不要反复重试或调快参数。
- **疑似微博接口变更**：可用浏览器开发者工具查看失败请求，对照 `extension/content.js` 顶部接口常量排查。分享错误信息时不要附带 Cookie、令牌或私信正文。

### 图片、视频或语音无法播放

媒体由本地服务后台排队下载，每个文件间隔约 2–4 秒，失败会自动重试，刚备份完成时可能还需要等待。私信附件可能需要微博登录 Cookie；服务重启后，刷新已登录的微博私信页，让扩展重新推送（Cookie 仅存内存）。

语音 AMR 转码需要 macOS 的 `afconvert` 或另行安装的 `ffmpeg`。未成功转码时，原始 `.amr` 仍可保留和下载，但浏览器可能无法直接播放。排查下载问题时查看启动终端；使用开机自启时查看 `data/server.log`。

## 项目结构

```
extension/            # Chrome 插件 (Manifest V3)
├── manifest.json
├── content.js        # 备份面板 + 限速引擎 + 被动捕获接收
├── injected.js       # MAIN world：捕获页面自身的 conversation.json 响应
├── background.js     # 转发请求到本地服务
└── popup.html/js     # 工具栏弹窗
server/               # 备份服务 (FastAPI)
├── app.py            # API + 静态站点
├── db.py             # SQLite 存储层（mid 去重 / 原始 JSON / 媒体队列）
├── media_worker.py   # 媒体下载线程（限速 + 防盗链 Referer + SHA256 去重）
├── export.py         # HTML 导出
├── static/           # 管理界面
└── templates/        # 导出模板
scripts/
├── gen_icons.py      # 重新生成插件图标
└── pack_extension.sh # 打包插件 zip
```
